# CARRY-OUT — claude-for-legal--claude-liam-aia-generation

**The sentence:**

> An AI Impact Assessment isn't finished when Claude writes it — it's finished when someone checks it against what the system actually does.

**Test:** if someone repeats only this in a meeting next week, is it still true? Yes —
it names the actual boundary (a fact-check against the real system) without naming any
tool's specific steps, so it survives being repeated out of context.

**The wrong guess it's built to defeat:** that a complete, well-written assessment is
therefore an accurate one — that once Claude drafts it, the compliance work is done. The
reel falsifies this with a concrete case (B01): a hiring tool described only as "matches
resumes to keywords" gets a fluent, correctly-written risk section — that simply omits the
video-interview scoring the real system also does, because Claude only ever saw the
description, never the system.

**Why this compresses the distinction that matters, not the topic:** the topic is
"AI Impact Assessments"; the distinction is *fluent vs. verified*. Every body beat exists
to make that distinction land — the three parts of a working assessment (system, data,
affected people) in B02 are what turn "someone checks it" into a checkable event rather
than a vague gesture at "human review."
