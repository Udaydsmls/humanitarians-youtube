# When Is an AI Impact Assessment Actually Finished?

Asking Claude to draft an AI Impact Assessment and getting back a complete,
well-written document feels like the job is done. It isn't — not yet. A
working assessment needs three things right: what the system actually does,
the data feeding it, and who it affects. Watch the anchor: a hiring tool
described only as "matches resumes to keywords" gets a fluent, correctly
written risk section that omits the video-interview scoring the real system
also does — because Claude only ever saw the description, never the system.
Only once that missing fact is added and checked does the assessment's
stamp flip from "unverified" to "verified." A fluent, complete-reading draft
doesn't prove accuracy, and a rough, half-filled one isn't a failure either
— both can be the process working exactly as intended.

## Deliberately not claimed

This reel is a reconstruction: the reel this one redoes had never had its
skill-specific facts written (its narration carried literal unfilled
template placeholders, and the SKILL.md file it pointed at doesn't exist on
this machine). Rather than invent specific product claims, this script
describes the generic shape of what makes an AI Impact Assessment accurate
— system, data, affected people — not any single skill's documented steps,
output format, or jurisdiction's legal requirement. It never claims Claude
made an error; the case in the reel is a description gap, executed
correctly.
