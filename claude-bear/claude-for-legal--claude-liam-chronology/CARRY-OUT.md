# CARRY-OUT — claude-for-legal--claude-liam-chronology

**The line (written first, GATE C):**

> A chronology isn't every date in order — it's each event named once, no
> matter how many documents mention it, and weighed by what this case is
> trying to prove.

**Test:** if someone repeats only this in a meeting next week, is it still
true? Yes — it compresses the one distinction the reel is built to land
(one entry per real event, weighted by the matter's theory), not the topic
(legal chronologies generally).

**The wrong guess it defeats:** that building a chronology means pulling
every date mentioned anywhere in the file and laying them in order. The
anchor (a late payment named in an email, an invoice, and a deposition
transcript — same day, three different documents) falsifies the guess
directly: a plain sorted list would print that one event three times.
Chronology building collapses it to one entry, then tags it by how much it
matters to the specific matter's theory — a tag that a different matter,
built on a different theory, would assign differently to the very same
event.
