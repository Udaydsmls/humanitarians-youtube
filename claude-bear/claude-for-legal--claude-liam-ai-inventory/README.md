# What's an AI Inventory?

A legal team's first instinct when AI tools start showing up is to write a
policy — a rule about which tools are allowed. But a policy can only govern
the tools someone remembered to name in it, and the ones adopted quietly
slip past every time. What actually closes that gap is an inventory: a
maintained list of every AI tool in use, what it does, what data touches it,
who owns it, and a risk tier. Watch the anchor: a contract-review tool one
team quietly adopted goes through the same four fields as everything else —
now it's visible instead of running unnoticed. Being logged doesn't mean a
tool is safe, and a list that looks complete today doesn't mean nothing's
missing tomorrow.

## YOUR TURN

"List every AI tool your team used this month — drafting help, research
search, document review, anything. For each one, write down what it does,
what data goes through it, and who owns it."

If any row comes up blank on "owner," that's the gap the inventory just
found — the exact gap a policy alone would never have caught.

## Deliberately not claimed

This reel is a reconstruction: the reel this one redoes had never had its
skill-specific facts written (its narration carried literal unfilled
template placeholders, and the SKILL.md file it pointed at doesn't exist).
Rather than invent specific product claims, this script describes the
generic shape of an AI-inventory governance practice — tool, data, owner,
risk tier — not any single tool's documented behavior. It never claims a
policy is useless, only that it has to follow the inventory, not precede
it.
