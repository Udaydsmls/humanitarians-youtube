# CARRY-OUT — GATE C

Written before any other narration. Every beat exists to make this sentence survivable.

## The line

> **A financial-modeling skill isn't Claude inventing a model from
> judgment — it's SKILL.md, a spec Claude reads and runs the same way
> against whatever numbers you hand it.**

## The wrong guess it defeats

That building a DCF or running a sensitivity table is Claude exercising
some general financial judgment, trained in from the model itself. It
isn't: `creating-financial-models` is a folder — `dcf_model.py`,
`sensitivity_analysis.py`, and a `SKILL.md` holding the full instruction
set in plain language. Claude reads the steps in order and executes them.
The file is the program.

## The secondhand test

*If someone repeats only this sentence in a meeting next week, is it still
true?*

Yes — it compresses the one distinction that matters (a skill is a spec
Claude reads and re-runs, not built-in financial judgment) and it doesn't
overstate what that spec guarantees: "the same way against whatever
numbers you hand it" also covers the source's own limit — a projection the
steps weren't written for still runs the same steps, against numbers
outside what `SKILL.md` names.

## What it deliberately does not say

- Not a verdict on whether the source skill's `SKILL.md` should have
  covered more scenario types or discount conventions (Teardown
  territory) — Plain states the mechanism and the limit, and stops.
- Not a claim about which specific formulas, discount rates, or Monte
  Carlo parameters the skill uses beyond what the source itself names
  ("DCF analysis, sensitivity testing, Monte Carlo simulations, and
  scenario planning for investment decisions") — the source `SKILL.md`
  isn't available on this machine, so nothing beyond its own narrated
  description is invented.
- Not a claim that the skill validates its input — only that it runs the
  same steps regardless of whether the projection fits the spec.
