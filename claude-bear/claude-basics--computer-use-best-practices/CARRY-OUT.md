# CARRY-OUT — GATE C

Written before any other narration. Every beat exists to make this sentence survivable.

## The line

> **Production isn't the demo running longer — it's every screenshot made
> leaner and every action logged, so the cost holds up and so does the
> record.**

## The wrong guess it defeats

That taking a working computer-use demo to production just means letting it
run on more steps, more tasks, for longer. It doesn't scale for free: a
20-step task with no changes can burn on the order of 40,000 screenshot
tokens before a single action token, and if a run goes wrong there is nothing
to check it against.

## The secondhand test

*If someone repeats only this sentence in a meeting next week, is it still true?*

Yes — it compresses the one distinction that matters (screenshots shrunk,
actions logged) without smuggling in a verdict on whether computer-use is a
good idea, or a claim about exactly how much any one deployment will save.

## What it deliberately does not say

- Not a cost guarantee for any specific deployment — the 70–80% figure is the
  source's reported range for resize + prune, not a promise.
- Not that trajectory logging prevents mistakes — a fully logged run still
  proves only what happened, not that it was the right action (BOTH-DIRECTIONS
  LAW, carried in B04).
- No verdict on whether computer-use is the right approach for a given task —
  that's a design judgment (Teardown's lane), not Plain's.
