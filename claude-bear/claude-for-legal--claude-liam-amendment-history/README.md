# Claude, Amendment History.

A contract gets signed, then amended more than once. The natural move when
someone needs to know what it says today is to pull up the original signed
document — but the original only ever says what it said on day one. It has
no way of knowing anything was signed after it. Amendment history walks the
chain in order instead, and for any one clause, only the most recent edit
counts. Watch the anchor: a lease's notice period set at thirty days in the
original, stretched to sixty by the first amendment, cut back to forty-five
by the second — what's in force today is forty-five, the last edit
standing, and only for that clause. A clause no amendment ever touched
isn't missing from the picture; the original wording still governs it. And
an amendment existing somewhere in the file doesn't mean it touched the
clause you're asking about — you still have to follow that clause's own
chain.

## YOUR TURN

"Paste in a contract along with every amendment to it. Go through this
clause by clause. For each one, tell me whether an amendment changed it,
and if so, give me only the most recent version — not the original."

Why it's worth running: the exercise surfaces the same distinction the
reel is built around — a clause-by-clause read catches every place the
original document alone would have given the wrong answer.

## Deliberately not claimed

This reel is a reconstruction: the reel this one redoes had never had its
skill-specific facts written (its narration carried literal unfilled
template placeholders, and the SKILL.md file it pointed at doesn't exist).
Rather than invent specific product claims, this script describes the
generic shape of tracking a legal document through a chain of amendments —
clause-level supersession — not any single tool's documented behavior. It
never claims amendments always supersede cleanly, only that the most
recent edit to a clause is what's in force for that clause.
