# CARRY-OUT — GATE C

Written before any other narration. Every beat exists to make this sentence survivable.

## The line

> **A Skill isn't new intelligence — it's a folder of fixed steps Claude
> reads before acting, so a one-click button does exactly what's written,
> every time, and nothing that isn't.**

## The wrong guess it defeats

That a Skill must be special code Claude runs — some compiled or hidden
logic bolted onto the model. It isn't: open the `action-creator` folder and
there's no program to execute, just a `SKILL.md` file (plain text you could
read in any editor) and a `templates` folder beside it. Two files. Claude
reads the file's Steps section and works through it top to bottom; nothing
in the folder runs on its own.

## The secondhand test

*If someone repeats only this sentence in a meeting next week, is it still true?*

Yes — it compresses the one distinction that matters (a Skill is fixed
instructions, not new capability) without overstating what a saved action
can do beyond its own file.

## What it deliberately does not say

- Not a claim that Skills can never be extended — only that *this* skill's
  button does only what its own `SKILL.md` currently specifies.
- Not a verdict on whether that design is good or limiting (Teardown
  territory) — Plain states the mechanism and the boundary, and stops.
- Not that every Skill has exactly this shape — `action-creator` is the
  worked example; the anatomy (SKILL.md + supporting files, Steps section)
  is the pattern this reel demonstrates, not a universal spec.
