# Claude, Unstuck

A plugin breaks, or a fix you found online doesn't match what's actually on
your screen — and the natural instinct is to go hunting for a solution that
matches your exact interface. That's the wrong target. Most breakage takes
one of five familiar shapes — won't appear, won't authenticate, generic
results, too slow, a command not found — and each one traces to a durable
cause: a mid-session install that hasn't reloaded, a stale credential, a
default still set broad, an operation reaching too far outside your
machine. A four-step loop clears most of it: active, authorized, simpler,
restart — and the middle step, shrinking a request until it breaks, tells
you exactly where the problem lives. The harder catch is that most updates
apply automatically, so the interface keeps shifting under you even while
the concept holds still. Verify specifics against the sources that stay
current — the plugin's own docs, the directory, the release notes —
because the screen dates, but the mental model doesn't.
